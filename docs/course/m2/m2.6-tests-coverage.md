# M2.6 · Tests: unit and integration, 80%+ coverage

> **Ticket:** [#41](https://github.com/Dfscashline21/sideline/issues/41) ·
> **Mode:** mixed: test *cases* by hand, boilerplate by agent ·
> **Time:** 4 to 5 hours · **Needs:** M2.3 to M2.5 merged

## Why this matters

You've been writing tests since M2.3. This ticket turns them into a
**suite**: realistic recorded responses instead of hand-typed JSON, one
test against real MinIO, and a coverage gate in CI so the suite can't
quietly rot.

Two acceptance criteria carry the lesson:

- **No live API calls in unit tests.** Live calls make tests slow, flaky
  and dependent on someone else's server. A test that fails because
  stats.nba.com was down tells you nothing about your code.
- **Coverage above 80% in CI.** Not because 80 is magic, but because the
  untested 20% should be a *choice* you can explain, not an accident.

## The mixed split

| You write by hand | An agent may draft (you review every line) |
|---|---|
| Which cases to test, and every assertion | The fixture-recording script |
| The fake API that replays fixtures | `conftest.py` fixtures and markers |
| The integration test's checks | CI workflow changes (services, coverage flags) |
| What to leave uncovered, and why | `pyproject.toml` config lines |

Rule of thumb: if it decides *what correct means*, it's yours.

## Steps

### 1. Measure where you are (15 min)

```bash
uv add --dev pytest-cov
uv run pytest ingestion --cov=sideline_ingestion --cov-report=term-missing
```

The `Missing` column lists uncovered line numbers. Expect `cli.py` and
`s3_store.py` to be low: nothing has exercised them without a live
network or MinIO yet. Write the starting total in your PR description.

### 2. Record real responses as fixtures (45 min, agent may draft)

Unit tests should replay **real** responses, not JSON you typed, so they
catch the shape the API actually returns. Have an agent draft
`ingestion/tests/fixtures/record.py`:

> Write a script that uses `sideline_ingestion.http.fetch_raw` to fetch
> one `leaguegamelog` for 2024-10-22 to 2024-10-23 and the
> `boxscoretraditionalv3` and `playbyplayv3` responses for one game ID
> from that log, saving each response's bytes unchanged to
> `ingestion/tests/fixtures/<entity>_<id>.json`. Run manually, never from
> tests. Typed, passes ruff and mypy.

Review: does it save `response.content` unchanged? Does it have a timeout
(via `fetch_raw`)? Is it impossible for pytest to collect it? (It isn't
named `test_*.py`, so it can't be.)

Then add one **hand-made** malformed fixture per entity (copy a real one
and break one relied-on field). These drive the M2.5 quarantine tests.

✅ **Checkpoint:** fixture files exist, and each is under the
`check-added-large-files` limit (500 KB by default). A full game's
play-by-play can approach that. If one is over, store it gzipped
(`.json.gz`) and decompress in the test loader rather than trimming it.
A trimmed fixture is no longer what the API returned.

### 3. A fake API that replays fixtures (45 min, by hand)

Two ways to replay, and you should know both:

- **`responses`**: intercepts `requests` at the HTTP layer. Best for
  `fetch_raw` tests, where status codes and retries matter.
- **A fake `fetch` callable**: because `nba.run` takes `fetch` as a
  parameter (M2.3), a test can pass a function that returns fixture bytes
  by URL. Best for extractor logic, where HTTP is irrelevant.

<details>
<summary>Hint · A fixture-backed fake fetch</summary>

```python
FIXTURES = Path(__file__).parent / "fixtures"


def fixture_fetch(url: str, params: Mapping[str, str]) -> bytes:
    endpoint = url.rsplit("/", 1)[-1]
    if endpoint == "leaguegamelog":
        return (FIXTURES / "game_log_20241022.json").read_bytes()
    entity = {"boxscoretraditionalv3": "boxscore", "playbyplayv3": "playbyplay"}[endpoint]
    return (FIXTURES / f"{entity}_{params['GameID']}.json").read_bytes()
```

Make it record its calls (a class with a `calls` list) so tests can
assert *how many* requests a run made. M2.7 needs exactly that.

</details>

### 4. Guarantee no live calls (15 min, by hand)

"No live calls" should be enforced, not hoped for. Options:

- Wrap every unit test that touches HTTP in `@responses.activate`: any
  unregistered URL raises `ConnectionError`.
- Or add an autouse fixture in `ingestion/tests/conftest.py` that
  replaces `requests.Session.get` (or `socket.socket.connect`) with a
  function that fails the test, for every test not marked `integration`.

Prove it works: temporarily write a test that calls the real URL, see it
fail with your guard's message, then delete it.

### 5. Fill the gaps (90 min, by hand)

Read the `Missing` lines file by file and decide, for each block, *test
it* or *leave it with a reason*. Likely gaps:

- **`cli.py`**: call `main(["--start", "2024-10-22", "--end",
  "2024-10-23"])` with `S3Store` and `fetch_raw` monkeypatched to a
  `MemoryStore` and the fixture fetch. Also the "up to date" path and the
  argument errors (`pytest.raises(SystemExit)` for bad dates).
- **`s3_store.py`**: covered by the integration test in step 6, not by
  mocking boto3. Mocking a client library mostly tests your mock.
- Error branches in `validate.py` and `watermark.py`.

✅ **Checkpoint:** total coverage above 80%, and you can explain every
remaining uncovered line.

### 6. One integration test against MinIO (60 min, mixed)

Register a marker so integration tests are opt-in-able (agent may draft):

```toml
[tool.pytest.ini_options]
markers = ["integration: needs MinIO from docker compose (make up)"]
```

Then write the test by hand:

- skip cleanly if MinIO isn't reachable (`pytest.skip` from a fixture
  that tries `S3Store(...).list_keys("")`), so `make test` still works
  with the stack down
- write under a **unique prefix per test run** (`test-runs/<uuid4>/`) and
  delete it afterwards. Random keys are fine *in a test* because the test
  owns the prefix. In the extractor they'd break idempotency.
- run `nba.run` with the fixture fetch against a real `S3Store`, then
  assert keys, bytes and the watermark through `S3Store` itself

<details>
<summary>Hint · Pointing the store at a test prefix</summary>

Either give `S3Store` an optional `prefix` argument that it prepends to
every key, or run against the real bucket and pass a test-only league
key such as `test_<uuid>`. The first is cleaner and is how you'd point
the same code at a staging prefix later.

</details>

### 7. Coverage gate in CI (30 min, agent may draft)

CI must start MinIO for the integration test and fail under 80%. Ask an
agent to change `.github/workflows/ci.yml` so that, before the test step,
it runs:

```yaml
- name: Start MinIO
  run: |
    cp .env.example .env
    docker compose up -d --wait minio minio-init
```

and the test step becomes:

```yaml
- name: Test (pytest)
  run: |
    set -a && . ./.env && set +a
    uv run pytest --cov=sideline_ingestion --cov-report=term-missing --cov-fail-under=80
```

Review points: `.env.example` values are the only credentials CI sees
(fine for a throwaway container; never real secrets). Does `make test`
match what CI runs? If not, update the Makefile so they can't drift
(the M0 principle).

✅ **Checkpoint:** push a branch with one test deleted to drop coverage
under 80% and watch CI fail. Restore it and watch CI pass. Link both runs
in the PR.

## Gotchas

- **`pythonpath = ["ingestion"]`** must be in the pytest config (M2.3
  step 2), or CI fails with `ModuleNotFoundError` even when it passes on
  a laptop where you ran from inside `ingestion/`.
- **Coverage counts lines run, not behaviour checked.** A test that calls
  `nba.run` with no assertions raises coverage and proves nothing. Every
  test needs an assertion that would fail if the code were wrong.
- **Tests that sleep.** If the suite takes more than a few seconds, a
  retry test isn't injecting `sleep`.
