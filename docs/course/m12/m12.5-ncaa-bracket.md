# M12.5 · Run the model on an NCAA tournament bracket

> **Ticket:** [#156](https://github.com/Dfscashline21/sideline/issues/156) ·
> **Mode:** mixed · **Time:** 4 hours ·
> **Needs:** M12.4 (a trained model), M12.2 college features, M7.3 college data

## Why this matters

A bracket is a point-in-time problem with a twist: you fill it in
**before the tournament starts**, so a second-round prediction can't use
first-round results, even though those games happen before the second
round tips off. It's the clearest real-world example of "what did we
know, and when?" Plus it's a fun result table that people actually read.

## What's hand, what's agent

| Part | Who | Why |
|---|---|---|
| Picking the tournament games and the **as-of cutoff** | **You** | This is the point-in-time logic |
| Adapting features for **neutral sites** | **You** | A modelling decision |
| Scoring: how you compare predictions to results | **You** | Defines what "good" means |
| Loading the schedule, rendering the results table, a chart | Agent may draft | Plumbing |

## What you'll produce

- `ml/bracket.py`: scores one past men's NCAA tournament
- A published **bracket results table**: each game, predicted winner and
  probability, actual winner, correct or not, round (the acceptance criterion)
- A short summary: accuracy by round, versus "always pick the better seed"
  or "always pick the better pre-tournament record"

## Steps

### 1. Identify the tournament games (hand, 30 min)

College postseason (`season_type = 3`) contains more than the NCAA
tournament: the NIT, CBI and CIT are in there too. The ESPN schedule data
(sportsdataverse release `espn_mens_college_basketball_schedules`, files
`mbb_schedule_<season>.parquet`) has a `tournament_id` and a
`notes_headline` that tell them apart.

Explore one season:

```sql
select tournament_id, count(*) as games, any_value(notes_headline) as example
from read_parquet('https://github.com/sportsdataverse/sportsdataverse-data/releases/download/espn_mens_college_basketball_schedules/mbb_schedule_2024.parquet')
where season_type = 3
group by 1 order by 2 desc;
```

✅ **Checkpoint:** for 2024 you find one tournament with **67 games**
(the "Men's Basketball Championship", 4 First Four games plus 63). That's
the one. If you got 120 games, you've included the other postseason
tournaments.

Pick the season to score, and decide whether the First Four counts. Also
check whether seeds are available in your data; if not, note it as a
missing baseline.

### 2. Set the as-of cutoff (hand, 30 min)

Two honest ways to score, and they answer different questions:

| Mode | Features as of | Answers |
|---|---|---|
| **Pre-tournament bracket** | Before the first tournament game, for **every** round | "How good is a bracket filled in on Selection Sunday?" |
| **Game by game** | Before each game's own tip-off | "How good is the model at predicting the next game?" |

The ticket says "score a past tournament", so do the **pre-tournament
bracket** as the main result. Every feature for every game must use the
same cutoff, the first tournament tip-off. Game by game is a good stretch.

<details>
<summary>Hint · Implementing a fixed cutoff</summary>

You already have `feat_team_game` keyed by game. For a fixed cutoff you
need features per **team** as of one timestamp: the team's last feature
row with `prediction_ts < cutoff`, or recomputed from all games before
the cutoff. `ASOF JOIN` each tournament team to its features on
`team_id` and `prediction_ts < cutoff`. Rest days and travel make little
sense for a fixed cutoff: drop them or set them neutral, and say so.

</details>

### 3. Handle neutral sites (hand, 30 min)

Your model learned "home team wins" with home advantage built in.
Tournament games are at neutral sites (check the `neutral_site` column).
Options:

- Predict both orientations (A home vs B, B home vs A) and average.
- If the model has an explicit home feature, set it to 0.

Write which and why. Ignoring it means the "home" team listed first gets
a free bonus that doesn't exist.

### 4. Let an agent draft the plumbing

> Write `ml/bracket.py`: given a season, load the NCAA men's tournament
> games (filter: *your rule from step 1*), load team features from
> *(your table or function)* with the cutoff I compute in
> `as_of_features()` (I'll write that function), call my model's
> `predict_proba` via `predict_neutral()` (I'll write that), and write a
> results table to `docs/blog/ncaa-<season>-bracket.md` with columns:
> round, game date, team A, team B, P(A wins), predicted winner, actual
> winner, correct. Add accuracy by round and overall, plus the baseline
> "better pre-tournament win %". Typed; passes lint and typecheck.

Write `as_of_features()` and `predict_neutral()` yourself first, so the
agent fills in only around them.

Review: is the cutoff applied to **every** game, including the final?
Does each round's game list come from the actual results (fine for scoring
each game), and is it clear that you're not simulating a bracket forward?
Are First Four games labelled?

### 5. Read the results

✅ **Checkpoint:** a table of all tournament games with predictions and
results, and accuracy by round.

Questions to answer in the summary:

- Where did the model do worst? Early rounds (many close games) or late?
- How many upsets did it call, and how many did it miss?
- Did it beat the simple baseline? Sixty-seven games is a small sample:
  one or two games swing accuracy by 3 points, so say how confident
  you are.

### 6. Publish

Link the table from the README's "numbers" section, or show it on the
M11.5 dashboard. Either counts as published.

## Gotchas

- **Other postseason tournaments.** Filter on the tournament, not on
  `season_type = 3`.
- **Women's tournament.** `ncaa_w` has its own schedule release
  (`espn_womens_college_basketball_schedules`). Scoring it too is a good
  stretch and strengthens the "all leagues" story.
- **Team ID consistency.** Make sure tournament games and your features
  use the same team IDs (both ESPN here, but check if your M7.3
  extractor used a different source).
