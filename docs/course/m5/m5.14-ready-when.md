# M5.14 · Ready-when check (closed-book)

> **Ticket:** [#81](https://github.com/Dfscashline21/sideline/issues/81) ·
> **Mode:** hand, closed-book · **Time:** 45 min ·
> **Needs:** M5.1 to M5.13 done

## Why this matters

The M5 promise: *explain when an incremental model silently produces
wrong numbers, and how you'd catch it.* That's a whiteboard conversation
in a senior interview, and the follow-ups go deep. If you need your notes
to answer, the module hasn't stuck yet.

## The rules

- **No AI, no notes, no docs, no running dbt** until the timer stops.
- Whiteboard or paper. Talk out loud; record yourself if you can.

## Steps

### 1. The explanation (15 minutes, timed)

Start the timer and answer this as if an interviewer asked it:

> "We have an incremental fact table that's been running for a year.
> Finance says last month's numbers are off. Walk me through every way an
> incremental model can silently produce wrong numbers, and for each one,
> how you'd have caught it."

Cover, without prompting:

- at least **four** failure modes (think: filter, key, strategy, upstream
  deletes, late data, schema change, timezone/event-time)
- for each, the **test or monitor** that catches it
- how you'd **recover** (lookback override, targeted rebuild, full refresh)
  and what that costs

### 2. Draw it (5 minutes)

Sketch a timeline of three incremental runs with a lookback window. Mark
a correction that lands inside the window and one that doesn't. Show
which rows each run touches.

### 3. One sealed scenario (10 minutes)

Pick **one** without reading the others (roll a die: 1–2 → A, 3–4 → B,
5–6 → C). Diagnose it out loud.

<details>
<summary>Scenario A</summary>

After a deploy, `fact_play` row counts per day are fine, but
`sum(points_scored)` for last Tuesday dropped by 18. Only last Tuesday.
The staging model changed its dedup ordering in the same deploy.

</details>

<details>
<summary>Scenario B</summary>

The `unique` test on `fact_shot.play_id` started failing on Monday. The
model hasn't changed in a month. The extractor team says they "re-ran the
weekend's load after an outage".

</details>

<details>
<summary>Scenario C</summary>

`dim_player` shows a player on his new team for the four days *before*
the trade was announced. Nothing errored. The snapshot config was changed
last week "to make it simpler".

</details>

### 4. Now check

Timer off. Open your M5.1 cheat sheet, ADR-004 and M5.10 test map.

| Result | Meaning |
|---|---|
| 4+ failure modes, each with a test and recovery; scenario diagnosed | **Pass.** |
| Fewer than 4, or tests missing for some | Redo M5.1 session 2 from a blank page, retry in 2 days with another scenario. |
| Scenario wrong | Repeat the lab it's about (A: M5.3/M5.6, B: M5.6/M5.7, C: M5.5). |

### 5. Write the notes

Append to `docs/notes/m5.md`:

```markdown
## Ready-when check (YYYY-MM-DD)
- Failure modes named: __ / tests named: __ · Scenario: A/B/C · Result: pass / retry
- Missed:

## Hardest part of M5
<three sentences: what was hardest and why>
```
