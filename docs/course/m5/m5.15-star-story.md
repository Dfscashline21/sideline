# M5.15 · STAR story from your current job

> **Ticket:** [#82](https://github.com/Dfscashline21/sideline/issues/82) ·
> **Mode:** hand · **Time:** 45 min ·
> **Prompt:** *A transformation at work with no tests or docs, and what a
> dbt-style approach changed or would change.*

The STAR format, word budgets and common mistakes are in the
[M0.9 lab](../m0/m0.9-star-story.md). Reread its table before starting.
This lab covers only what's specific to a transformation story.

## Finding the story

Questions to jog memory:

- A stored procedure, SSIS package or notebook that nobody dared touch
  because nobody knew what depended on it.
- A number that changed overnight with no code change: upstream data
  shifted and nothing tested it.
- Business logic (a revenue rule, a customer definition) copied into
  several reports, each slightly different. That's M5.9's semantic-layer problem.
- A late-arriving correction that never made it into a report: M5.6's
  problem, at work.

The prompt allows "would change": if you never got to fix it, your Action
can be the proposal you made, the prototype you built, or the first
tests you added.

## What makes this story strong

- **One concrete failure** with a cost: a wrong report sent to N people,
  hours spent reconciling, an incident.
- **The specific practice** you introduced, named precisely: tests on
  keys, a staging layer, documentation, lineage, CI on SQL changes.
  "Brought in dbt" alone is vague; "added uniqueness and reconciliation
  tests that caught a duplicate load the next month" is a story.
- **A before/after number**: incidents per quarter, time to answer "where
  does this number come from?", onboarding time for a new analyst.

## Follow-ups to prepare

Write a one-line answer to each:

1. "How did you get buy-in to add tests to something that 'worked'?"
2. "What would you test first in a legacy pipeline with no tests at all?"
3. "What did it cost, and was it worth it?"

## Where to save it

Private notes alongside your other STAR stories, **never** this repo.
Close the issue with "Saved to private notes" and no details.

## Done when

- [ ] S, T, A, R in under 200 words
- [ ] Includes a number (time saved, cost, incidents, rows or people)
- [ ] Saved to private notes, not the public repo
- [ ] Three follow-up answers drafted
