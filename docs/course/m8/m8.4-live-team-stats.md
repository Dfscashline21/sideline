# M8.4 · Stream job: live team stats with event time

> **Ticket:** [#110](https://github.com/Dfscashline21/sideline/issues/110) ·
> **Mode:** hand · **Time:** 4 to 6 hours ·
> **Needs:** M8.1 sessions 1 and 2, M8.2, M8.3, M7.5 (local PySpark)

## Why this matters

This is the first job where **when** something happened and **when you
heard about it** are different columns, and the answer depends on which
one you use. Group by processing time and a replay at 10x gives
different "per-minute" stats from a replay at 60x. Group by event time
and both give the same answer as the box score. Proving that is the
acceptance criterion and the core streaming skill.

## What you'll produce

`streaming/jobs/live_team_stats.py`: a Spark Structured Streaming job that:

- reads `game-events` from Redpanda and decodes the Avro values
- uses `event_time` with a **30-second watermark**
- aggregates per game, per team, per **1-minute event-time window**:
  points, FGM/FGA, 3PM, FTM/FTA, offensive and defensive rebounds, turnovers
- writes results somewhere you can query

Plus a check showing the totals equal the batch box score
(`nba_team_box`) after the game.

The ticket offers Flink or Spark. These labs use **Spark Structured
Streaming** as the primary path because you already run PySpark from M7.
You'll compare it with Flink properly in M8.10.

### 2. Decode the events (45 min)

Read the topic as a stream with `startingOffsets` = `earliest`. Each row
has binary `key` and `value`, plus `timestamp` (the Kafka timestamp M8.3
set).

The value is in the **Confluent wire format**: 1 magic byte, a 4-byte
schema ID, then the Avro body. Spark's `from_avro` expects only the body.

`substring` in Spark SQL is 1-based. Which position does the Avro body
start at, if the first five bytes are the header?

</details>

```python
from pyspark.sql.avro.functions import from_avro

schema_json = Path("streaming/schemas/game_event.avsc").read_text()

events = raw.select(
    from_avro(F.expr("substring(value, ___, length(value) - ___)"), schema_json).alias("e")
).select("e.*")
```

Avro `timestamp-millis` arrives as a Spark `timestamp`. Check with
`events.printSchema()`.

</details>

Use the console sink first to see decoded rows scroll past while the
producer runs at 60x.

✅ **Checkpoint:** `event_time` is a `timestamp` column, team IDs and
scores look right for game 401584089 (IND 11 vs CLE 5).

### 3. Define each stat as an expression (45 min)

Before writing the stream, work out each stat from event columns on the
**batch** practice data in DuckDB, and check it against `nba_team_box`.
That gives you trusted definitions before streaming adds complexity.

| Stat | From play-by-play |
|---|---|
| Points | `sum(score_value)` where `scoring_play` |
| FGA | shooting plays that aren't free throws |
| FGM | scoring plays that aren't free throws |
| 3PM | scoring plays with `score_value = 3` |
| FTA, FTM | `event_type like 'Free Throw%'`, made = `scoring_play` |
| OREB, DREB | `event_type` = `Offensive Rebound` / `Defensive Rebound` (includes team rebounds: see Gotchas) |
| TOV | your turnover set from M1.5 |

✅ **Checkpoint:** for game 401584089 your DuckDB query gives IND 121 /
CLE 116 points, FGA 86 / 84, 3PM 15 / 8, FTA 24 / 25, matching the box score.
(Checked: points from play-by-play match `team_score` for 99.7% of
2023-24 team-games.)

### 4. Window on event time with a watermark (60 min)

<details>
<summary>Hint 1 · Nudge</summary>

`withWatermark` has to be applied to the **same column** you window on,
and **before** the aggregation. Otherwise Spark can't use it to drop state.

</details>

<details>
<summary>Hint 2 · Skeleton</summary>

```python
stats = (
    events.withWatermark("event_time", "___")
    .groupBy(F.window("event_time", "___"), "game_id", "team_id")
    .agg(
        F.sum(F.when(F.col("scoring_play"), F.col("score_value")).otherwise(0)).alias("pts"),
        # FGA, FGM, 3PM, FTA, FTM, OREB, DREB, TOV
    )
)
```

</details>

### 5. Choose an output mode and sink (60 min)

You need the final numbers in a queryable place to compare with the box
score. Think through the options before choosing:

- **Append** emits a window once, after the watermark passes its end. Clean,
  but the **last** minute of the game never emits, because no later event
  arrives to push the watermark forward. (M8.3's end-of-game marker is
  still inside the last window.)
- **Update** emits a window's row every time it changes. Every row is the
  window's current total, so the sink must **replace**, not add.

<details>
<summary>Hint · A sink that fits update mode</summary>

`foreachBatch` gives you each micro-batch as a normal DataFrame and its
`batch_id`. Upsert the rows into a Postgres table (you have Postgres in
Compose) keyed by `(game_id, team_id, window_start)`:
`INSERT … ON CONFLICT (game_id, team_id, window_start) DO UPDATE SET …`.
Upserts make a replayed batch harmless, which is the idea you'll
formalise in M8.7. A micro-batch here is a few rows, so
`batch_df.collect()` plus `psycopg` is fine.

</details>

Always set `checkpointLocation` (e.g. `.data/checkpoints/live_team_stats`).
Delete it when you want to re-run a game from scratch.

### 6. Prove it matches the box score (45 min)

1. Recreate the topic, start the job, replay game 401584089 at 60x with
   **no** chaos.
2. When the producer finishes, wait for one more trigger, then sum your
   windows per team and compare with `nba_team_box`, column by column.
3. Replay with chaos (`--late-fraction 0.05 --max-delay 10`). The totals
   must **still** match. Why 10 and not 29? This game's own events are
   already up to 18 seconds out of order (see Gotchas), and chaos adds to
   that: 18 + 10 stays inside the 30-second watermark.
4. Replay at 10x. The per-window numbers must match the 60x run exactly.
   That's the event-time guarantee in action.

✅ **Checkpoint:** all three runs give the same team totals, equal to the box
score. Record the comparison table in `streaming/README.md`.

<details>
<summary>Solution (open only after you have your own)</summary>

```python
"""Live team stats per 1-minute event-time window (M8.4)."""

from pathlib import Path

import psycopg
from pyspark.sql import DataFrame, SparkSession
from pyspark.sql import functions as F
from pyspark.sql.avro.functions import from_avro

PACKAGES = "org.apache.spark:spark-sql-kafka-0-10_2.13:4.1.4,org.apache.spark:spark-avro_2.13:4.1.4"
SCHEMA = Path("streaming/schemas/game_event.avsc").read_text()
UPSERT = """
    insert into live_team_stats (game_id, team_id, window_start, pts, fga, fgm, fg3m, fta, ftm, oreb, dreb, tov)
    values (%s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s)
    on conflict (game_id, team_id, window_start) do update set
      pts = excluded.pts, fga = excluded.fga, fgm = excluded.fgm, fg3m = excluded.fg3m,
      fta = excluded.fta, ftm = excluded.ftm, oreb = excluded.oreb, dreb = excluded.dreb, tov = excluded.tov
"""


def count_if(cond: F.Column) -> F.Column:
    return F.sum(F.when(cond, 1).otherwise(0))


def upsert(batch: DataFrame, batch_id: int) -> None:
    rows = [
        (
            r.game_id,
            r.team_id,
            r.window.start,
            r.pts,
            r.fga,
            r.fgm,
            r.fg3m,
            r.fta,
            r.ftm,
            r.oreb,
            r.dreb,
            r.tov,
        )
        for r in batch.collect()
    ]
    if rows:
        with psycopg.connect(
            "postgresql://sideline:change-me-local-only@localhost:5432/sideline"
        ) as conn:
            conn.cursor().executemany(UPSERT, rows)


def main() -> None:
    spark = (
        SparkSession.builder.appName("live_team_stats")
        .config("spark.jars.packages", PACKAGES)
        .config("spark.sql.shuffle.partitions", "4")
        .getOrCreate()
    )
    raw = (
        spark.readStream.format("kafka")
        .option("kafka.bootstrap.servers", "localhost:19092")
        .option("subscribe", "game-events")
        .option("startingOffsets", "earliest")
        .load()
    )
    # Skip the 5-byte Confluent header (magic byte + schema id); substring is 1-based.
    events = (
        raw.select(from_avro(F.expr("substring(value, 6, length(value) - 5)"), SCHEMA).alias("e"))
        .select("e.*")
        .where(F.col("team_id").isNotNull())
    )

    is_ft = F.col("event_type").startswith("Free Throw")
    turnovers = (
        F.lower("event_type").contains("turnover") & (F.col("event_type") != "No Turnover")
    ) | F.col("event_type").isin("Traveling", "Offensive Foul", "Offensive Charge")
    stats = (
        events.withWatermark("event_time", "30 seconds")
        .groupBy(F.window("event_time", "1 minute"), "game_id", "team_id")
        .agg(
            F.sum(F.when(F.col("scoring_play"), F.col("score_value")).otherwise(0)).alias("pts"),
            count_if(F.col("shooting_play") & ~is_ft).alias("fga"),
            count_if(F.col("scoring_play") & ~is_ft).alias("fgm"),
            count_if(F.col("scoring_play") & (F.col("score_value") == 3)).alias("fg3m"),
            count_if(is_ft).alias("fta"),
            count_if(is_ft & F.col("scoring_play")).alias("ftm"),
            count_if(F.col("event_type") == "Offensive Rebound").alias("oreb"),
            count_if(F.col("event_type") == "Defensive Rebound").alias("dreb"),
            count_if(turnovers).alias("tov"),
        )
    )
    (
        stats.writeStream.outputMode("update")
        .foreachBatch(upsert)
        .option("checkpointLocation", ".data/checkpoints/live_team_stats")
        .trigger(processingTime="5 seconds")
        .start()
        .awaitTermination()
    )


if __name__ == "__main__":
    main()
```

This assumes your schema has a `shooting_play` field; add it in M8.2 if
you left it out (a compatible change with a default). Credentials are
inline for brevity; read them from `.env` in your version.

</details>

## Gotchas

- **Pick your test game on purpose.** Before any chaos, the source data
  has events that arrive behind the newest event seen so far. For game
  401584089 the worst is 18 seconds, inside the watermark. But in about
  half of 2023-24 games (577 of ~1,230), at least one event is more than
  30 seconds behind on its own, so it would be dropped even with zero
  chaos. Measure a game before using it as a "clean" test:

  ```sql
  -- seconds each event is behind the newest event seen before it
  with g as (
      select game_play_number, wallclock::timestamptz as ts
      from nba_pbp where game_id = 401584089 and wallclock is not null
  ), behind as (
      select epoch(max(ts) over (order by game_play_number
                   rows between unbounded preceding and 1 preceding) - ts) as secs
      from g
  )
  select max(secs) from behind;   -- 18.0 for this game
  ```

  That this happens in real data is a finding worth a sentence in your
  ADR (M8.10): is 30 seconds the right threshold for this feed?
- **Team rebounds.** Play-by-play rebound counts include **team**
  rebounds; the box score's `offensive_rebounds` mostly doesn't (M1.5
  found about 5.7 more per team-game). Points, FGA, 3PM and FTA should
  match exactly; for rebounds, either match the box-score definition or
  document the difference.
- **`spark.sql.shuffle.partitions`** defaults to 200. On one laptop with one
  game, that's 200 nearly-empty tasks per micro-batch, and a very slow job.
- **Stale checkpoints.** If you change the aggregation and keep the old
  checkpoint, Spark may refuse to start, or resume with incompatible
  state. Delete the checkpoint when you change the query's shape.
- **Topic retention.** Rerunning a game appends to the topic. Either
  recreate the topic or filter by `game_id` and use a fresh checkpoint.
