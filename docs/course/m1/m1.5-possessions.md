# M1.5 · Possessions as sessions

> **Ticket:** [#30](https://github.com/Dfscashline21/sideline/issues/30) ·
> **Mode:** hand · **Time:** 3 to 4 hours (the hardest M1 problem) ·
> **Needs:** M1.3 (islands), M1.2 (`nba_pbp`, `nba_team_box`)

## Why this matters

**Sessionization** means grouping a stream of events into sessions: web
clicks into visits, app events into user sessions, telemetry into trips.
The interview version is "a session ends after 30 minutes of
inactivity". The SQL pattern is always the same: **flag where a new
session starts, then a running sum of the flags is the session ID**.

Basketball possessions are sessionization with a harder rule: a
possession ends when the *other team* gets the ball. Real event data is
messy, so you'll also practise the second skill this ticket tests:
validating a result against an independent estimate and explaining the
gap.

## What you'll produce

`sql/problems/003_possessions.sql` that:

1. Assigns every relevant play-by-play event a possession ID.
2. Counts possessions per game.
3. Compares them to the box-score estimate for **10 sample games**.

Plus documented edge cases: and-ones, offensive rebounds, end of period.

## Background: what's a possession?

A possession is a spell where one team has the ball. It ends with a made
basket (except an and-one, where the free throw comes first), a defensive
rebound, a turnover, the last made free throw of a trip, or the end of a
period. An **offensive** rebound does *not* end it.

The standard **box-score estimate**, per team per game:

```
possessions ≈ FGA − ORB + TOV + 0.44 × FTA
```

`0.44 × FTA` approximates free-throw *trips* (most trips are 2 shots,
some 1 or 3, some are and-ones that don't add a possession). Sum both
teams to get a per-game total comparable to yours.

## Steps

### 1. Explore one game's events (30 min)

```sql
select game_play_number, period_number, clock_display_value,
       type_text, team_id, scoring_play, text
from nba_pbp
where game_id = (select min(game_id) from nba_pbp where season = 2024 and season_type = 2)
order by game_play_number
limit 60;
```

Read it like a commentator. For each row, say out loud which team has
the ball **after** the event. Then:

```sql
select type_text, count(*) n, any_value(text) example
from nba_pbp group by 1 order by 2 desc;
```

Sort the ~140 event types into buckets: **shots**, **free throws**,
**rebounds**, **turnovers**, and **noise** (substitutions, timeouts,
fouls…). This is the real work of the lab.

✅ **Checkpoint:** you've noticed that some turnovers don't have
"Turnover" in their name, and that `team_id` on a turnover row is the team
that **lost** the ball.

### 2. Define the offence for each event

For each meaningful event, which team is on offence?

- Shots, free throws, turnovers, offensive rebounds: `team_id` (the
  acting team).
- Defensive rebounds: `team_id` is the rebounding team, which is now on
  offence. That's the start of *their* possession.

Drop the noise events entirely. They don't change who has the ball.

### 3. Sessionize

Now it's a pattern you know: a new possession starts whenever the offence
team differs from the previous event's, or a new period starts.

<details>
<summary>Hint 2 · Approach</summary>

1. `lag(offense_team) over (partition by game_id, period_number order by game_play_number)`
2. `is_new = (prev is null or offense_team <> prev)` as 1/0
3. `sum(is_new) over (partition by game_id order by period_number, game_play_number)` is the possession number

This is the general sessionization recipe. For a 30-minute-inactivity
rule, step 2 would compare timestamps instead.

Note: M1.3's `row_number` difference gives the same answer here. Try
both; know both.

</details>

<details>
<summary>Hint 3 · Skeleton</summary>

```sql
with ev as (
    select game_id, period_number, game_play_number, team_id as offense_team
    from nba_pbp
    where season = 2024 and season_type = 2 and team_id is not null
      and ( ___ )                      -- your shot / FT / turnover / rebound buckets
),
flagged as (
    select *,
        case when lag(offense_team) over w is distinct from offense_team then 1 else 0 end as is_new
    from ev
    window w as (partition by game_id, period_number order by game_play_number)
),
sessions as (
    select *, sum(is_new) over (partition by game_id order by period_number, game_play_number) as possession_id
    from flagged
)
select game_id, max(possession_id) as possessions
from sessions
group by game_id;
```

`is distinct from` treats `NULL` (first event of a period) as different,
so each period starts a new possession.

</details>

### 4. Compare with the box-score estimate

Compute the estimate from `nba_team_box` (sum both teams per `game_id`),
join to your counts, and show the % difference for 10 games. Pick the
10 games **before** you look at the results (e.g. the first 10
`game_id`s of the season), so you can't cherry-pick.

✅ **Checkpoint, and an honest expectation.** On the 2023-24 regular
season, a correct event-based count comes out about **2 to 3% below** the
`0.44` estimate on average, with roughly two-thirds of games within 3%.
If your gap is much bigger, look for a missing turnover type or a wrong
defensive-rebound rule.

### 5. Explain the gap (this is the senior part)

A consistent negative bias isn't a bug in *your* query. It tells you
something about the *estimate*. Investigate at least two causes and write
them up:

- Try `0.40 × FTA` instead of `0.44`. (In testing, 0.40 cut the average
  gap to about 1.6% with ~84% of games within 3%.) Why might the modern
  NBA need a smaller coefficient? Think about and-ones and technical
  free throws.
- Compare `count(*) filter (where type_text = 'Offensive Rebound')` from
  the play-by-play with `offensive_rebounds` in the box score. The
  play-by-play includes **team** rebounds (ball out of bounds off a
  defender); the box score doesn't. Which way does that push the estimate?

If your 10 sample games aren't all within 3% with the standard formula,
the acceptance criterion is met by **documenting why**, with numbers, and
showing the variant that matches. That's what you'd do at work.

### 6. Document the edge cases

In the file's header, explain how your query handles each case and

- **And-one:** made shot, then a foul, then 1 free throw by the same team.

- **Offensive rebound:** why is it the same possession?
- **End of period:** what ends the last possession of a quarter?

<details>
<summary>Solution (open only after you have your own)</summary>

```sql
-- Problem:  Group play-by-play events into possessions; compare with box-score estimate
-- Pattern:  sessionization (LAG flag + running SUM)
-- Tables:   nba_pbp, nba_team_box
with ev as (
    select game_id, period_number, game_play_number, team_id as offense_team
    from nba_pbp
    where season = 2024 and season_type = 2 and team_id is not null
      and type_text <> 'No Turnover'
      and (shooting_play                                  -- field goals and free throws
           or type_text ilike '%turnover%'
           or type_text in ('Offensive Rebound', 'Defensive Rebound',
                            'Traveling', 'Offensive Foul', 'Offensive Charge'))
),
flagged as (
    select *,
        case when lag(offense_team) over w is distinct from offense_team then 1 else 0 end as is_new
    from ev
    window w as (partition by game_id, period_number order by game_play_number)
),
poss as (
    select game_id, sum(is_new) as possessions from flagged group by game_id
),
est as (
    select game_id,
        sum(field_goals_attempted - offensive_rebounds + total_turnovers
            + 0.44 * free_throws_attempted) as est_044,
        sum(field_goals_attempted - offensive_rebounds + total_turnovers
            + 0.40 * free_throws_attempted) as est_040
    from nba_team_box
    where season = 2024 and season_type = 2
    group by game_id
)
select game_id, possessions,
    round(est_044, 1) as est_044, round(100 * (possessions - est_044) / est_044, 1) as pct_diff_044,
    round(est_040, 1) as est_040, round(100 * (possessions - est_040) / est_040, 1) as pct_diff_040
from poss join est using (game_id)
order by game_id
limit 10;
```

Why this handles the edge cases without special code: an and-one's
free throw is by the *same* team as the made shot, so no offence change,
so no new possession. Likewise an offensive rebound. A defensive rebound
is credited to the new offence, so it opens their possession. Periods are
partitions, so each period's last possession closes there. Choosing the
right *representation* (who has the ball) removed most of the special cases.

</details>

## Gotchas

- **Event order.** Order by `game_play_number`, not by clock: several
  events share a clock value (foul, then free throws, then substitutions).
- **`team_id` NULL rows** (end of period, some timeouts) must be dropped
  or they break the `lag` comparison.
- **`sum(is_new)` vs `count(distinct possession_id)`** should agree.
  If they don't, your partitions differ between the two windows.
