## Why this matters

"Top N per group" is the single most frequently asked window-function
question. The two places candidates lose points are exactly this
ticket's acceptance criteria: **ties** and **filtering in the wrong
place**. It's also the query you'll profile and speed up in M1.7, so
write it cleanly.

## What you'll produce

`sql/problems/004_top3_true_shooting.sql`: top 3 men's college players by
TS% in each season, minimum 100 shot attempts, ties returning every tied
player.

## Background: true shooting %

TS% measures scoring efficiency, counting 3-pointers and free throws
properly:

```
TS% = PTS / (2 × (FGA + 0.44 × FTA))
```

The `0.44 × FTA` term is the same free-throw-trip approximation as in
M1.5.

## Steps

### 1. Define the terms (write them in the header)

- **"Shot attempts"**: field-goal attempts (FGA) only, or "true shooting
  attempts" (`FGA + 0.44 × FTA`)? Either is defensible; the threshold
  changes who qualifies. Pick one.
- **Season**: regular season only, or including the tournament
  (`season_type = 3`)?
- **DNPs**: do they matter for sums? (Check: what are `points` and
  `field_goals_attempted` on a DNP row?)

### 2. Aggregate to player-season

One row per player per season, with total points, FGA, FTA and TS%.
Group by `athlete_id`, not by name: two different players can share a
name.

✅ **Checkpoint:** row count is in the tens of thousands per season, and
no player appears twice in one season. Check it with a
`group by season, athlete_id having count(*) > 1` query.

### 3. Filter, then rank (order matters)

### 5. Prove the tie handling with a fixture

Real seasons rarely have exact ties in TS%, so your real results can't
prove the criterion. Build a tiny test table with known ties and run
your ranking logic on it:

```sql
with fixture(season, athlete_id, pts, fga, fta) as (
    values (2024, 1, 200, 100, 0),   -- TS% 1.000
           (2024, 2, 180, 100, 0),   -- 0.900
           (2024, 3, 160, 100, 0),   -- 0.800
           (2024, 4, 160, 100, 0),   -- 0.800  tied with player 3 for third
           (2024, 6, 140, 100, 0),   -- 0.700
           (2024, 5, 300,  50, 0),   -- 3.000, but only 50 attempts: must be excluded
           (2025, 11, 200, 100, 0),  -- 1.000
           (2025, 12, 180, 100, 0),  -- 0.900
           (2025, 13, 180, 100, 0),  -- 0.900  tied with player 12 for second
           (2025, 14, 160, 100, 0)   -- 0.800  fourth place: must be excluded
)
-- your aggregate → filter → rank logic, pointed at fixture
```

✅ **Checkpoint:** 2024 returns players 1, 2, 3 and 4 (both players tied
for third). 2025 returns 11, 12 and 13 only. Player 5 never appears.

- Only three players in 2024? Your function drops ties (`row_number`).
- Player 14 in 2025? Your function counts distinct *values*, not places
  (`dense_rank`): two players tied for second leave 0.800 in fourth
  place, not third.

Compare with your step 4 table.

### 6. Run it on the real data

Sanity-check the results: do the names look like efficient big men and
shooters? A TS% above 0.80 with 100+ attempts is rare. If you see
several, recheck the formula's parentheses.

<details>
<summary>Solution (open only after you have your own)</summary>

```sql
-- Problem:  Top 3 men's college players by TS% per season, min 100 FGA, ties included
-- Pattern:  aggregate → filter (HAVING) → rank (RANK + QUALIFY)
-- Tables:   ncaa_player_box
-- Decisions: regular season only; "shot attempts" = FGA; DNP rows excluded
with player_season as (
    select season, athlete_id,
           any_value(athlete_display_name) as player,
           any_value(team_short_display_name) as team,
           sum(points) as pts,
           sum(field_goals_attempted) as fga,
           sum(free_throws_attempted) as fta
    from ncaa_player_box
    where season_type = 2 and not did_not_play
    group by season, athlete_id
    having sum(field_goals_attempted) >= 100          -- filter BEFORE ranking
)
select season, player, team, fga,
       round(pts / (2 * (fga + 0.44 * fta)), 4) as ts_pct,
       rank() over (partition by season order by pts / (2 * (fga + 0.44 * fta)) desc) as ts_rank
from player_season
qualify ts_rank <= 3
order by season, ts_rank;
```

`rank()` keeps everyone tied *within* the top 3 and still means "at most
3 places". `dense_rank() <= 3` would return three distinct TS% *values*,
which could be 10 players.

</details>

## Gotchas

- **`any_value(team)`**: a transfer mid-season (rare in college, common
  in the NBA) makes this arbitrary. Fine for display; never group by it.
- **Integer arithmetic.** `pts / (2 * fga)` with integer columns could
  truncate in other databases. DuckDB's `/` returns a double, but
  writing `2.0` makes the intent clear everywhere.
- **Division by zero.** Your filter guarantees `fga >= 100`, but if you
  ever drop the filter, `0 / 0` returns NULL or errors depending on
  the database.
