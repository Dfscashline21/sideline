# M9.7 · Lineage with OpenLineage

> **Ticket:** [#125](https://github.com/Dfscashline21/sideline/issues/125) ·
> **Mode:** agent: the agent drafts, you review it like a junior's PR ·
> **Time:** 3 hours · **Needs:** Dagster (M6) and dbt (M5) running locally

## Why this matters

When a gold number is wrong, the first question is "where did it come
from?", and the second is "what else uses it?". **Lineage** answers both:
upstream for root cause, downstream for impact. In M9.8 you'll break
things on purpose; lineage is how you'll see which dashboards and tables
each break reaches.

OpenLineage is the open standard for lineage *events*: jobs emit "run
started / completed, read these datasets, wrote these datasets", and a
backend (here, Marquez) stitches the events into a graph.

## What you'll produce

- Marquez (API + web UI) in `compose.yaml`.
- dbt runs emitting lineage via `dbt-ol`.
- Dagster ingestion assets emitting lineage for raw → staging.
- A lineage graph in the Marquez UI for one gold table (e.g.
  `fact_team_game`) that reaches back to the raw zone. That's the
  acceptance criterion; screenshot it for your notes.

## Background: the pieces (read before prompting)

| Piece | What it is | Status, Nov 2026 |
|---|---|---|
| [`openlineage-dbt`](https://pypi.org/project/openlineage-dbt/) | Wrapper: run `dbt-ol build` instead of `dbt build` | Active (1.55.x); lists `duckdb` among supported adapters |
| [`openlineage-python`](https://pypi.org/project/openlineage-python/) | Client to emit events yourself | Active (1.55.x) |
| [`openlineage-dagster`](https://pypi.org/project/openlineage-dagster/) | Official sensor that tails Dagster's event log | Last release Oct 2025 (1.38.0); its README asks for new maintainers; op-level, not asset-centric |
| [`dagster-openlineage`](https://pypi.org/project/dagster-openlineage/) | Third-party, asset-centric integration | 0.2.x; no author or project URL listed on PyPI. Review the source before trusting it |
| Marquez `marquezproject/marquez` + `marquez-web` | Lineage backend and UI | 0.51.1; needs a Postgres database |

So the Dagster side is a real **decision**, which you make, not the
agent. A reasonable default for this repo: `dbt-ol` for dbt, and a small
helper that emits events with `openlineage-python` from your ingestion
assets (a dozen lines you can fully explain). Record the choice and
why in the PR; ADR-worthy if you like.

## Steps

### 1. Decide dataset names first (20 min)

Lineage only connects if the job that **writes** a dataset and the job
that **reads** it use the *same* namespace and name. Decide the naming
for each layer before anything emits:

| Layer | Namespace | Name | Example |
|---|---|---|---|
| Raw zone (MinIO) | `s3://sideline-raw` | key prefix | `nba/nba_api/team_game_log` |
| Iceberg / DuckDB tables | ___ | ___ | `staging.stg_nba__team_game_log` |

Then check what name `dbt-ol` actually gives a dbt **source** with your
adapter (run it once and inspect the event, step 4). Your ingestion
helper must emit the *same* string for the dataset it writes, or the
graph breaks into two islands.

✅ **Checkpoint:** a written naming table in the PR description.

### 3. Review it like a pull request

| Review question | What a good answer looks like |
|---|---|
| Does a lineage failure fail the pipeline? | No: transport errors are caught and logged, with a timeout |
| Are image and package versions pinned? | Exact tags and `==`/lockfile versions |
| Are ports and credentials from `.env`? | Yes, added to `.env.example` with local-only defaults |
| Do START and COMPLETE share a `runId`? | Yes; otherwise Marquez shows two half-runs |
| Are dataset names identical to the naming table? | Character for character |
| Is a FAIL event sent when an asset raises? | Yes, then the exception is re-raised |
| Does `make up` still pass on a fresh clone (M0.8)? | Marquez healthy, no port clashes |

Ask the agent to explain anything you can't. In particular: what's the
difference between a **job**, a **run** and a **dataset** in OpenLineage?
If you can't answer that, you're not done.

### 4. Run it and inspect a raw event (30 min)

Before trusting the UI, look at one event. Point the client at a file or
console transport (see the `openlineage-python` docs for transport
configuration), run one dbt model, and read the JSON: `eventType`, `job`,
`run.runId`, `inputs`, `outputs`. Check the dataset names against your
naming table.

✅ **Checkpoint:** you can point at the field in the event that links
this run's input to the previous run's output.

### 5. Get the graph for a gold table

Run the full daily pipeline for one league and day. Open Marquez, find
`fact_team_game` (or your chosen gold table), and open its lineage view.
It should show the path back through staging to the raw dataset written
by the ingestion asset.

helper (not dbt), and re-run.

</details>

Screenshot the graph into `docs/notes/m9.md`.

## Gotchas

- **Port 5000 on macOS** is taken by AirPlay Receiver, and Marquez's API
  defaults to it. Remap the host port rather than disabling AirPlay.
- **Two things on port 3000.** Dagster's webserver and `marquez-web`
  both default to it.
- **Column-level lineage** needs `catalog.json`: `dbt-ol` reads it if
  `dbt docs generate` has run. Nice to have; not required by the ticket.
- **Partitioned assets.** One Dagster partition run = one OpenLineage
  run. Make sure your `runId` is unique per partition run, not per asset.
