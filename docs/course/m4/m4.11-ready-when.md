# M4.11 · Ready-when check (closed-book)

> **Ticket:** [#66](https://github.com/Dfscashline21/sideline/issues/66) ·
> **Mode:** hand, closed-book · **Time:** 45 min ·
> **Needs:** M4.1 to M4.10 done

## Why this matters

The M4 promise: *draw Iceberg's metadata tree from memory and explain how
a query skips files.* In an interview this is a whiteboard question,
followed by "and what happens when…?" follow-ups. If you can only answer
with the spec open, the module hasn't stuck yet.

## The rules

- **No AI, no notes, no docs, no running anything** until the timer stops.
- Whiteboard or paper. Talk out loud as if to an interviewer, and record it
  if you can.

## Steps

### 1. Draw the tree: 10 minutes, timed

From the catalog down to Parquet row groups. Label:

- what each level is (catalog, metadata file, snapshot, manifest list,
  manifest, data file, row group)
- what each level **stores that helps skip data**
- which file a reader opens first, second, third

### 2. Walk through file skipping: 10 minutes, still closed-book

Use this query on your `raw.pbp` table, as it is now (after M4.4's
partition evolution):

```sql
select count(*)
from raw.pbp
where team_id = 7 and game_date between '2026-01-01' and '2026-01-31';
```

Explain, step by step, out loud:

1. Which metadata file is read, and how the reader finds it.
2. How the manifest list lets it skip manifests.
3. How each manifest lets it skip data files, **for files written under
   the old spec and under the new spec** (they differ!).
4. What Parquet does inside each surviving file.
5. Roughly how many files survive, and why.

### 3. Answer three follow-ups: 5 minutes

Pick three without looking ahead (roll a die twice, or ask someone):

1. What changes if I ask for this query as of last Monday?
2. I add a column. Which of the levels you drew change?
3. Why can't you just partition by `athlete_id_1`?
4. A streaming job commits every 10 seconds. What goes wrong over a week?
5. What does compaction change in your drawing, and what doesn't it change?
6. What exactly does the catalog store, and why must it be strongly consistent?

### 4. Check it

Timer off. Compare your drawing with the spec and your M4.1 tree. Then
run the query with `EXPLAIN ANALYZE` in DuckDB, and count planned files in
PyIceberg. How close was your estimate?

### 5. Score yourself honestly

| Result | Meaning |
|---|---|
| Tree right, skipping explained for both specs, follow-ups answered | **Pass.** Close the ticket. |
| Tree right, but fuzzy on manifest-level skipping or mixed specs | Not yet. Redo M4.1 session 3 and M4.4 step 4, retry in 2 days. |
| Levels missing or in the wrong order | Redo M4.1 from session 3, then retry. |
