# M4.5 · Schema evolution: add shot coordinates

> **Ticket:** [#60](https://github.com/Dfscashline21/sideline/issues/60) ·
> **Mode:** hand · **Time:** 2 to 3 hours ·
> **Needs:** M4.3 (`raw.pbp` loaded without coordinates)

## Why this matters

Sources grow new fields. In a folder of plain Parquet, adding a column
means old files don't have it, readers that match by **position** read
the wrong column, and renames silently break queries. Iceberg tracks
columns by **ID**, so adding, renaming or reordering is a metadata change,
and old files read new columns as NULL.

The second half matters as much as the first. Once a column is NULL for
most of history, every query that uses it must handle that honestly:
"average shot distance by season" must not quietly average only the
seasons that have data and present it as a trend.

## What you'll produce

- `ingestion/sideline_ingestion/lakehouse/evolve_schema.py`: adds
  `coordinate_x`, `coordinate_y` (shot location) and `points_attempted` to
  `raw.pbp`, then backfills **2021 onwards only**.
- Proof that a pre-change snapshot is still readable with its old schema.
- Two queries that handle historical NULLs correctly.

## Background: what's in the source

| Column | In ESPN files from | Notes |
|---|---|---|
| `points_attempted` | 2021 | The column exists from 2021, but it's only **sparsely** filled until 2026: in a check, ~29k of 545k rows in 2021, under 5k in 2022 and 2024, every row in 2026 |
| `coordinate_x`, `coordinate_y` | 2002 | Present in every season, **but** non-shot events hold a sentinel of about ±214,748,000, and free throws have `coordinate_y = 0` |

So the realistic story here: "the source added `points_attempted` in
2021, and only started filling it properly in 2026; we're adding shot
coordinates at the same time and backfilling the same seasons". That's
two kinds of historical NULL in one table: **column didn't exist** and
**column existed but wasn't populated**. Backfilling coordinates for
every season is a stretch goal, because it's a cost decision, not a
technical one.

<summary>Solution (open only after you have your own)</summary>

```python
"""Add shot coordinates and points_attempted to raw.pbp; backfill 2021 onwards.

Coordinates: ESPN encodes "no location" as roughly +/-214,748,000 on non-shot
events. That isn't a value, so raw stores NULL instead, for everything except
field-goal attempts. This is the one deliberate deviation from "raw is unchanged".
"""

import duckdb
from pyiceberg.table import Table
from pyiceberg.types import DoubleType, IntegerType

from sideline_ingestion.lakehouse.catalog import get_catalog
from sideline_ingestion.lakehouse.load_pbp import SOURCE, TABLE

BACKFILL_SEASONS = range(2021, 2027)
FIELD_GOAL = "shooting_play and type_text not like 'Free Throw%'"
# Target column -> source expression, where they differ.
EXPRESSIONS = {
    "league": "'nba'",
    "play_id": "id",
    "coordinate_x": f"case when {FIELD_GOAL} then coordinate_x end",
    "coordinate_y": f"case when {FIELD_GOAL} then coordinate_y end",
}


def add_columns(table: Table) -> None:
    existing = set(table.schema().column_names)
    with table.update_schema() as update:
        if "coordinate_x" not in existing:
            update.add_column("coordinate_x", DoubleType(), doc="Shot x in feet; NULL if not a FGA")
        if "coordinate_y" not in existing:
            update.add_column("coordinate_y", DoubleType(), doc="Shot y in feet; NULL if not a FGA")
        if "points_attempted" not in existing:
            update.add_column("points_attempted", IntegerType(), doc="From source; 2021 onwards")


def backfill_season(table: Table, season: int) -> int:
    select = ", ".join(
        f"{EXPRESSIONS.get(name, name)} as {name}" for name in table.schema().column_names
    )
    url = SOURCE.format(season=season)
    df = duckdb.sql(f"select {select} from read_parquet('{url}')").to_arrow_table()
    table.overwrite(df.cast(table.schema().as_arrow()), overwrite_filter=f"season = {season}")
    return int(df.num_rows)


def main() -> None:
    table = get_catalog().load_table(TABLE)
    add_columns(table)
    for season in BACKFILL_SEASONS:
        print(f"season={season} rows={backfill_season(table, season)}")


if __name__ == "__main__":
    main()
```

`update_schema()` with no changes inside commits nothing, so a re-run
is safe.

</details>

### 6. Queries that handle historical NULLs (30 min)

Write both in `sql/problems/` with the usual header:

1. **Average shot distance by season.** Distance in feet from
   `sqrt(coordinate_x² + coordinate_y²)` is close enough here. The result
   must **not** show 2002 to 2020 as if they had data. Return them as NULL
   with a `coverage` column, or exclude them with a comment saying why.
2. **Share of field-goal attempts that were threes, by season**, using

   seasons show NULL rather than a misleading percentage computed from a
   few thousand populated rows: a rule like "only report when coverage
   ≥ 95%" makes the decision explicit.

<details>
<summary>Hint 3 · The trap in query 1</summary>

`avg()` skips NULLs. Over all seasons, `avg(distance)` returns an
average of 2021 to 2026 only. The answer is right for those seasons and
misleading as "all-time". Always pair it with `count(coordinate_x)` and
`count(*)` so a reader can see coverage.

</details>

## Gotchas

- **Column order on cast.** New columns are appended at the end of the
  schema. Building the `select` from `table.schema().column_names` keeps
  the order right automatically.
- **Renames are safe; type changes mostly aren't.** Iceberg allows
  widening (`int` → `long`, `float` → `double`) but not narrowing or
  `string` → `int`. Try `update.update_column("score_value", LongType())`
  in your study catalog to see what's allowed.
- **Name mapping.** Files written *outside* Iceberg (no field IDs) need a
  name mapping to be read. Not an issue here; worth knowing for M7.
