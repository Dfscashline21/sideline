> **Prompt:** *A storage or file-layout problem at work (small files, slow

The STAR format, word budgets and common mistakes are in the
[M0.9 lab](../m0/m0.9-star-story.md). Reread its table before starting.
This lab covers only what's specific to a storage story.

## Finding the story

You don't need a lakehouse at work. Storage and layout problems show up
everywhere. Questions to jog memory:

- **Slow scans:** a table or file share where every query read
  everything. A report that got slower every month as data grew. A
  missing index, partition or clustering key.
- **Small files or too many objects:** thousands of tiny CSVs in a folder,
  a nightly export that wrote one file per customer, an S3 or blob listing
  that took minutes, a Spark job slowed by tiny files.
- **No history:** "what did this table say last week?" with no answer.
  An overwritten config, a corrected invoice with no audit trail, a
  restore from backup just to compare numbers.
- **Schema breakage:** a source added or renamed a column and something
  downstream silently read the wrong field.

If your fix was a process rather than a technology (a snapshot table, an
archive step, a naming convention), that counts.

## What makes a storage story strong

- **A before/after number:** query or job runtime, files or objects
  count, storage cost, hours spent reconstructing history.
- **The mechanism, in one sentence:** *why* it was slow ("every query
  listed 40,000 files before reading any"). This is where M4 gives you
  vocabulary: pruning, file skipping, compaction, snapshots.
- **The trade-off you accepted:** compaction jobs to maintain, retention
  limits, migration effort.

## Follow-ups to prepare

Write a one-line answer to each:

1. "How did you find the cause?"
2. "What would you do differently with a table format like Iceberg or
   Delta?" (Your M4 work is the answer: be specific.)
3. "How do you stop it coming back?"

## Where to save it

Private notes alongside your other STAR stories, **never** this repo.
Close the issue with "Saved to private notes" and no details.

- [ ] Includes a number (runtime, files, cost, rows or people)
