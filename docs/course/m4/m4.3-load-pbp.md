# M4.3 · Load NBA play-by-play since 2002 into Iceberg

> **Ticket:** [#58](https://github.com/Dfscashline21/sideline/issues/58) ·
> **Mode:** hand · **Time:** 3 to 4 hours ·
> **Needs:** M4.2 (catalog running), M4.1 sessions 3 and 4, M1.7's `bench.py`

## Why this matters

This is the table every other M4 lab changes, so it's also your
**baseline**. Getting three things right here pays off all module:

- **Partitioning by a transform** (`month(game_date)`), so readers prune
  by date without knowing the partition exists.
- **Verifiable loads.** "Table loaded" means nothing until the row count
  matches an independent source.
- **A recorded baseline** you'll beat (or fail to beat) in M4.4 and M4.7.

## What you'll produce

- `ingestion/sideline_ingestion/lakehouse/load_pbp.py`: loads ESPN NBA
  play-by-play, seasons 2002 to 2026, into `raw.pbp`, partitioned by
  `month(game_date)`, one season per commit, safe to re-run.
- A row-count check against the source files.
- A baseline timing for one player's season, in `docs/notes/m4.md`.

## Steps

### 1. Choose the columns (30 min)

The ESPN pbp files have 64 to 69 columns, and the set drifts between
seasons (see the [module overview](README.md#know-these-before-you-start)).
Pick an **explicit** column list that exists in every season from 2002.
At minimum you need:

`game_id`, `id` (rename to `play_id`), `sequence_number`, `season`,
`season_type`, `game_date`, `period_number`, `clock_display_value`,
`type_text`, `text`, `team_id`, `athlete_id_1`, `athlete_id_2`,
`scoring_play`, `score_value`, `home_score`, `away_score`

Add a literal `league` column (`'nba'`). M4.4 will partition on it and
WNBA and college data will join this table later.

**Leave out the shot coordinates on purpose.** Adding them later is
M4.5's whole point.

Check your list is present in the oldest and newest files:

```sql
select name from parquet_schema('https://github.com/sportsdataverse/sportsdataverse-data/releases/download/espn_nba_pbp/play_by_play_2002.parquet');
```

### 2. Define the schema and partition spec explicitly (30 min)

Write the Iceberg `Schema` by hand with field IDs, and pass the
`PartitionSpec` to `create_table`.

<details>
<summary>Hint 1 · Why not just pass the Arrow schema?</summary>

You can: `catalog.create_table("raw.pbp", schema=arrow_table.schema)`
works. But then you have to add the partition field afterwards with
`update_spec()`, which leaves an empty, unpartitioned **spec 0** in the
table's history forever. It's harmless, but confusing when M4.4 asks you
to show which specs exist. Defining the schema yourself also makes the
types a decision rather than an accident (is `play_id` a `long`?).

</details>

<details>
<summary>Hint 2 · Skeleton</summary>

```python
from pyiceberg.partitioning import PartitionField, PartitionSpec
from pyiceberg.schema import Schema
from pyiceberg.transforms import MonthTransform
from pyiceberg.types import BooleanType, DateType, IntegerType, LongType, NestedField, StringType

SCHEMA = Schema(
    NestedField(1, "league", StringType()),
    NestedField(2, "game_id", IntegerType()),
    NestedField(3, "play_id", LongType()),
    # ... one per column, IDs 1..N
)
SPEC = PartitionSpec(
    PartitionField(
        source_id=___, field_id=1000, transform=MonthTransform(), name="game_date_month"
    ),
)
```

`source_id` is the **field ID** of `game_date`, not its position.

</details>

### 3. Write the loader (90 min)

Structure: a `main()` that ensures the namespace and table exist, then
loops seasons 2002 to 2026, and for each season:

1. reads the remote Parquet with DuckDB, selecting your columns in
   **schema order**
2. converts to an Arrow table and casts it to the table's Arrow schema
3. commits it as one snapshot, **replacing** any existing rows for that season
4. logs season, rows written and seconds taken

<details>
<summary>Hint 3 · Making a re-run safe</summary>

`table.append(df)` on a re-run doubles the season. Use
`table.overwrite(df, overwrite_filter=f"season = {year}")`: it
deletes rows matching the filter and adds the new ones in the same
operation. Because every file in this table holds one month, and no
month spans two seasons, the delete removes whole files rather than
rewriting them.

Check the "no month spans two seasons" claim yourself for 2020 to 2021
(the bubble season ended in October 2020; when did 2021 start?).

</details>

<details>
<summary>Hint 4 · The two errors you'll probably hit</summary>

- `NotImplementedError: Writing a pa.RecordBatchReader to a partitioned
  table is not yet supported`: DuckDB's `.arrow()` returns a reader.
  Use `.to_arrow_table()`.
- `ValueError: Target schema's field names are not matching`: Arrow's
  `cast` needs the same column **order**. Select columns in schema order,
  or `df.select(table.schema().column_names)` before casting.

</details>

<details>
<summary>Solution (open only after you have your own)</summary>

```python
"""Load ESPN NBA play-by-play (2002 to 2026) into Iceberg table raw.pbp."""

import time

import duckdb
from pyiceberg.catalog import Catalog
from pyiceberg.exceptions import NoSuchTableError
from pyiceberg.partitioning import PartitionField, PartitionSpec
from pyiceberg.schema import Schema
from pyiceberg.table import Table
from pyiceberg.transforms import MonthTransform
from pyiceberg.types import BooleanType, DateType, IntegerType, LongType, NestedField, StringType

from sideline_ingestion.lakehouse.catalog import get_catalog

TABLE = "raw.pbp"
SEASONS = range(2002, 2027)
SOURCE = (
    "https://github.com/sportsdataverse/sportsdataverse-data/releases/download/"
    "espn_nba_pbp/play_by_play_{season}.parquet"
)

SCHEMA = Schema(
    NestedField(1, "league", StringType()),
    NestedField(2, "game_id", IntegerType()),
    NestedField(3, "play_id", LongType()),
    NestedField(4, "sequence_number", IntegerType()),
    NestedField(5, "season", IntegerType()),
    NestedField(6, "season_type", IntegerType()),
    NestedField(7, "game_date", DateType()),
    NestedField(8, "period_number", IntegerType()),
    NestedField(9, "clock_display_value", StringType()),
    NestedField(10, "type_text", StringType()),
    NestedField(11, "text", StringType()),
    NestedField(12, "team_id", IntegerType()),
    NestedField(13, "athlete_id_1", IntegerType()),
    NestedField(14, "athlete_id_2", IntegerType()),
    NestedField(15, "scoring_play", BooleanType()),
    NestedField(16, "score_value", IntegerType()),
    NestedField(17, "home_score", IntegerType()),
    NestedField(18, "away_score", IntegerType()),
)
SPEC = PartitionSpec(
    PartitionField(source_id=7, field_id=1000, transform=MonthTransform(), name="game_date_month")
)
# Source column expressions, in SCHEMA order.
SELECT = ", ".join(
    ["'nba' as league", "game_id", "id as play_id"] + [f.name for f in SCHEMA.fields[3:]]
)


def get_or_create_table(catalog: Catalog) -> Table:
    catalog.create_namespace_if_not_exists("raw")
    try:
        return catalog.load_table(TABLE)
    except NoSuchTableError:
        return catalog.create_table(TABLE, schema=SCHEMA, partition_spec=SPEC)


def load_season(table: Table, season: int) -> int:
    url = SOURCE.format(season=season)
    df = duckdb.sql(f"select {SELECT} from read_parquet('{url}')").to_arrow_table()
    df = df.cast(table.schema().as_arrow())
    # Replace the season, so re-running never duplicates rows.
    table.overwrite(df, overwrite_filter=f"season = {season}")
    return int(df.num_rows)


def main() -> None:
    table = get_or_create_table(get_catalog())
    for season in SEASONS:
        start = time.perf_counter()
        rows = load_season(table, season)
        print(f"season={season} rows={rows} secs={time.perf_counter() - start:.1f}")


if __name__ == "__main__":
    main()
```

Why `SCHEMA.fields[3:]`: the first three columns are computed or renamed
(`league`, `play_id`); every later column has the same name in source
and table. Fine for a one-off load, but a dict of `target: source
expression` would be clearer if the mapping grew.

</details>

### 5. Record the baseline (30 min)

Pick one player's season. A good choice is Nikola Jokić in 2023-24
(`athlete_id_1 = 3112335`). Time two versions of the query with your M1.7
harness, median of 7 runs after a warm-up, through DuckDB attached to
the catalog:

```sql
-- A: filter on the partition source column
select count(*), sum(score_value)
from lake.raw.pbp
where athlete_id_1 = 3112335 and game_date between '2023-10-01' and '2024-06-30';

-- B: filter on season instead
select count(*), sum(score_value)
from lake.raw.pbp
where athlete_id_1 = 3112335 and season = 2024;
```

For each, also record **how many files the scan plans** (PyIceberg:
`len(list(table.scan(row_filter=...).plan_files()))`).

<details>
<summary>Hint · What to expect, and why it's interesting</summary>

A prunes by partition: only the months between October and June
survive. Surprisingly, B prunes almost as well, even though `season` isn't
a partition column. Every file holds one month, so each file's `season`
min and max are equal, and manifest **column bounds** let the planner skip
the rest. In a test on three seasons, both filters planned 9 of 27
files. Hidden partitioning isn't the only pruning mechanism; well-clustered
data gets column-stat pruning for free.

</details>

laptop, data size, date.

## Gotchas

- **Downloads dominate load time.** If you iterate on the loader, cache
  the Parquet files in `.data/espn_pbp/` first, so a bug doesn't cost you
  another 440 MB.
- **`text` is the biggest column.** It's free-form commentary. You keep it
  in raw because raw keeps everything (ADR-001's argument), but notice
  how it affects file size.
- **String filters keep mypy happy.** PyIceberg 0.12's expression classes
  (`EqualTo("season", 2024)`) work at runtime but fail the repo's mypy
  config. Its string filters (`"season = 2024"`) are parsed into the same
  expressions and type-check cleanly.
- **Don't partition by `game_id` or `athlete_id`.** Thousands of tiny
  partitions mean thousands of tiny files. M4.7 shows why that hurts.
