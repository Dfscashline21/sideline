# M0.8 · Ready-when check (closed-book)

> **Ticket:** [#24](https://github.com/Dfscashline21/sideline/issues/24) ·
> **Mode:** hand, closed-book · **Time:** 30 min ·
> **Needs:** M0.6 and M0.7 merged

## Why this matters

The M0 epic's promise is: *a stranger can clone the repo and run `make up`
to a working environment in under 10 minutes.* Until you've timed it from
a genuinely fresh state, that's a hope, not a fact.

"Closed-book" means **no AI, no notes, no study guide**. Only the README,
because that's all a stranger would have. If you need anything the
README doesn't say, that's a README bug: write it down.

## What you'll produce

- A timed run, fresh clone → healthy stack → tests passing, under 10 minutes.
- `docs/notes/m0.md` with the time, what slowed you down, and three
  sentences on what was hardest in M0 and why.

## Before the clock starts (allowed to use notes)

A clone on the same laptop isn't fresh by default. Three things leak
from your existing setup and make the time look better than a stranger's:

1. **Same Compose project.** `compose.yaml` sets `name: sideline`, so a
   second clone in another folder controls the *same* containers and
   volumes as your main checkout. Stop them first:

   ```bash
   cd ~/Documents/GitHub/sideline && make down
   ```

2. **Volumes.** MinIO and Postgres data survive `make down`. A stranger
   starts with none. Wiping them is safe now (nothing real is stored yet)
   but **won't be later**, so think before you do this after M2:

   ```bash
   docker compose down -v
   ```

3. **Images and caches.** Your images are already pulled and the dev image
   is built. For a truly cold run, remove them:

   ```bash
   docker image ls | grep -E 'silo|mc|postgres|sideline'
   docker image rm <the ids you see>
   ```

   Decide whether to also clear uv's cache (`uv cache clean`). A stranger
   would have an empty one. Note your choice in the notes either way.

Also check ports 9000, 9001 and 5432 are free (`lsof -i :5432`), because
a local Postgres install is the most common reason this fails.

## The timed run (closed-book from here)

1. Open a new terminal. Start a stopwatch.
2. Clone into a throwaway folder:

   ```bash
   cd "$(mktemp -d)" && git clone https://github.com/Dfscashline21/sideline.git && cd sideline
   ```

3. Follow **only** the README's "Run locally" section, command by command.
4. Prove the environment works. Decide what "working" means before you
   start. A sensible bar is:
   - `make ps`: every long-running service shows `healthy`
   - the MinIO console loads at http://localhost:9001 and the
     `sideline-raw` bucket exists
   - `make lint`, `make typecheck` and `make test` pass on the host
   - `docker compose exec dev pytest` passes inside the container
5. Stop the clock. Write down the time.

✅ **Checkpoint:** under 10:00. If not, note which step ate the time.

## If it fails or runs long

That's a successful check: it found something. In order:

1. Write down exactly where you got stuck and what the README was missing.
2. After the clock, fix the README (or Makefile) on a branch and PR it.
3. Redo the timed run. The ticket isn't done until a clean run passes.

Typical causes worth recognising:

| Symptom | Likely cause |
|---|---|
| `port is already allocated` | Another Postgres/MinIO on your laptop, or your main checkout's stack still running |
| `minio-init` exits non-zero | MinIO wasn't healthy yet, or `.env` credentials differ from the volume's existing ones |
| `uv: command not found` | README assumes uv is installed: should it say how to install it? |
| Very slow first `make up` | Image pulls plus the dev image build: is it network or build time? `docker compose up` prints both |

## Clean up

```bash
make down          # in the throwaway clone
cd ~/Documents/GitHub/sideline && make up    # back to your normal stack
```
