# M7.3 · College extractor (men's and women's)

> **Ticket:** [#96](https://github.com/Dfscashline21/sideline/issues/96) ·
> **Mode:** agent: the agent drafts, you review it like a junior's PR ·
> **Time:** 3 hours · **Needs:** M7.2 (quota design and guard), your NBA
> extractor (M2) and WNBA extractor (M6.2) as the pattern

## Why this matters

This is the third extractor built on the same pattern. If the pattern is
good, an agent can apply it to a new league in an afternoon; if it
isn't, you'll find out now. The skills practised are **specifying a
change by pointing at existing code** and **reviewing for the
guarantees that matter**: idempotency and budget safety. "It runs" is
not the bar.

## What you'll produce

- `ingestion/sideline_ingestion/college.py` (or your package's
  equivalent) covering `ncaa_m` and `ncaa_w`.
- Tests proving the quota guard is enforced and the idempotency
  guarantees match the NBA extractor's.

## Steps

### 1. Write down the guarantees you're asking for (20 min)

Reread your NBA extractor and its tests, then list what it guarantees.
These are what the college extractor must also guarantee (the ticket says
"same idempotency guarantees as NBA"). Typically:

- raw files land **unchanged** in `sideline-raw` (ADR-001)
- the object key layout from M2.2, with `league=ncaa_m` / `ncaa_w`
- re-running the same date range produces **no duplicates**
- kill mid-run, restart: correct data, no duplicates (your M2.7 test)
- watermarks and `--start/--end` backfills work per league
- row counts logged per run

Then add the college-specific ones:

- **every** CollegeBasketballData.com call goes through the M7.2 guard
- ESPN-file data never touches the API (per your design doc)
- men's and women's are separate leagues end to end (keys, watermarks)

### 2. Prompt the agent (15 min)

Adapt this, pasting your lists:

> `ingestion/sideline_ingestion/wnba.py`, their tests,

>

> Data sources and call budget are defined in the design doc. Every
> CollegeBasketballData.com API call must go through `CallBudget.reserve`.
>
> Guarantees to keep: *(paste step 1)*
>
> Reuse shared helpers instead of copying them. If you'd need to change

### 3. Review (60 min)

Read the diff before running anything. Answer each in your PR description:

| Review question | What a good answer looks like |
|---|---|
| Is there **any** API call path that skips the guard? Search for every `cbbd.` / HTTP call | Zero. Retries call `reserve` again, or reserve up front for the worst case |
| When is quota reserved: before the call, or after? | Before. After means a crash can spend calls you never recorded |
| What happens to the raw zone when a run is refused halfway? | Nothing partial is visible; same atomic-write rule as NBA |
| Did it copy NBA code or reuse it? | Shared helpers imported; league-specific parts small |
| Are `ncaa_m` and `ncaa_w` separate in keys and watermarks? | Yes, so a men's backfill can't move the women's watermark |
| Does it filter the ESPN `- Team` total rows? | Raw lands unchanged, so **no**: that's staging's job (M7.4). Check it didn't "clean" raw |
| Are source player IDs kept exactly as the source gives them (ESPN `athlete_id`, CBBD player IDs)? | Yes, untouched. M7.4 maps them through `player_crosswalk(source, source_player_id)` to the durable `player_id`; an extractor that renames or casts them breaks that join |
| Is the API key read from the environment? | `os.environ["CBBD_API_KEY"]`, never a literal, never logged |

<details>
<summary>Hint · Things agents get wrong on this ticket</summary>

- Calling `datetime.now()` inside the guard path, which makes month
  rollover untestable. Push it to the caller.
- Mocking the guard in the extractor tests so they pass trivially.
  At least one test must use a real (in-memory) budget that runs out.
- "Helpfully" dropping duplicate or team rows in the extractor. Raw
  stays raw.
- One combined watermark for both college leagues.

</details>

### 4. Run it small, then check (45 min)

Start with one week of one league, from files only (no quota spent):

```bash
uv run python -m sideline_ingestion.college --league ncaa_w --start 2025-03-01 --end 2025-03-07
```

(Use whatever CLI shape your NBA extractor has.) Then:

1. Run the same command again. Object count in MinIO unchanged? Your
   staging row counts unchanged?
2. Run your kill-and-restart test (M2.7) against the college extractor.
3. Set the budget limit artificially low (e.g. 2 calls), run something
   that needs the API, and confirm it's refused **and** nothing landed.
4. Check the quota table: does `used` match the number of real calls
   you saw in the logs?

✅ **Checkpoint:** a second run is a no-op, the low-budget run is refused
cleanly, and the counter matches reality.

### 5. Backfill plan (15 min)

Don't backfill everything today. Write in `docs/notes/m7.md` how many
seasons you'll load from files now, and which API datasets you'll
backfill over which months, according to your budget.

### 6. Ship it

```bash
make lint && make typecheck && make test
gh pr create --fill     # Closes #96; paste review answers from step 3
```

## Gotchas

- **Women's and men's file names differ** (`espn_womens_…` vs `espn_mens_…`)
  but the schemas are very similar. A shared loader with a league parameter
  is fine; a shared watermark is not.
- **Season labelling:** like the NBA files, `season` is the year the
  season *ends* (2025 = 2024-25).
- **Live-season files change daily.** Idempotency tests should use
  completed seasons so results are stable.
