# M7.5 · Local Spark with Iceberg

> **Ticket:** [#98](https://github.com/Dfscashline21/sideline/issues/98) ·
> **Mode:** agent: the agent drafts, you review it like a junior's PR ·
> **Time:** 2 to 3 hours · **Needs:** M7.1 (Spark installed), M4.2
> (Iceberg REST catalog in Compose), M5 (tables written by dbt/DuckDB)

## Why this matters

The point of an open table format is that **any engine reads the same
tables**. Until now DuckDB (and dbt on DuckDB) wrote and read your
Iceberg tables. If Spark can read exactly what they wrote, with no
copies or exports, you've proven the lakehouse works as advertised. The
setup is fiddly (versions, jars, S3 endpoints), which is exactly why it
belongs in one reviewed module, not in every job.

## What you'll produce

- `spark/sideline_spark/session.py`: one function that returns a
  SparkSession wired to your Iceberg REST catalog on MinIO.
- A test or smoke script proving Spark reads tables written by DuckDB/dbt,
  with matching row counts.
- A Make target, e.g. `make spark-shell`.

## Steps

### 1. Collect the facts the agent needs (20 min)

From your repo, not memory:

- Catalog URI and warehouse name from `compose.yaml` (M4.2), e.g.
  `http://localhost:8181` and `sideline-lake`
- MinIO endpoint as seen **from your laptop** (`http://localhost:9000`)
  and from inside Compose (`http://minio:9000`)
- Credentials: the variable names in `.env`
- Two tables dbt wrote, with their row counts from DuckDB, e.g.
  `marts.fact_play`, `marts.dim_player`

Verified version facts (November 2026):

| Item | Value |
|---|---|
| PySpark | `==4.1.4` (same pin as M8). Iceberg has no runtime for Spark 4.2 or 4.3 yet |
| Iceberg runtime | `org.apache.iceberg:iceberg-spark-runtime-4.1_2.13:1.12.0` |
| S3 support | `org.apache.iceberg:iceberg-aws-bundle:1.12.0` |
| SQL extensions | `org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions` (needed for `MERGE INTO`, M7.8) |

### 2. Prompt the agent (15 min)

> Read `AGENTS.md` and `compose.yaml`. Write
> `spark/sideline_spark/session.py` with a typed function
> `get_spark(app_name: str, *, shuffle_partitions: int = 8) -> SparkSession`
> that runs Spark in local mode and registers an Iceberg catalog named
> `lake` (the name M8 also uses), type `rest`, against our REST catalog at `http://localhost:8181`, using `S3FileIO`
> against MinIO. Use these packages: *(versions above)*. Read endpoints
> and credentials from environment variables with the names in
> `.env.example`; add any new ones there with placeholder values.
> Enable the Iceberg SQL extensions. Set `spark.sql.shuffle.partitions`
> from the argument. Add `pyspark==4.1.4` to a `spark` dependency
> group if it isn't there. Explain every config key in a comment.
>
> Also write `spark/tests/test_iceberg_read.py`, marked as an integration
> test, that reads `lake.marts.fact_play` and asserts its row count
> equals the count DuckDB reports for the same table.

### 3. Review (45 min)

| Review question | What a good answer looks like |
|---|---|
| Catalog keys | `spark.sql.catalog.lake` = `org.apache.iceberg.spark.SparkCatalog`, `.type` = `rest`, `.uri`, `.warehouse` |
| File IO | `.io-impl` = `org.apache.iceberg.aws.s3.S3FileIO`, `.s3.endpoint` = MinIO, `.s3.path-style-access` = `true` |
| Credentials | From environment; not printed in logs; nothing new committed |
| Region | Something sets a region (`AWS_REGION` env, or the catalog's `client.region`). The AWS SDK fails without one, even for MinIO |
| Jar versions | Exactly the pinned ones; Spark minor version in the artifact name matches installed PySpark |
| Shuffle partitions | Set low for local runs, with a comment why (default 200) |
| One place | Every later job imports `get_spark`; no copy-pasted builder configs |

Ask the agent to explain any key you can't. Look each one up in the
[Iceberg Spark configuration docs](https://iceberg.apache.org/docs/latest/spark-configuration/)
before accepting it.

<details>
<summary>Hint · The usual reasons it doesn't connect</summary>

- **Wrong Spark/Iceberg pairing.** `pyspark` 4.3 with a `4.1` runtime jar
  fails with class or method errors at startup. Pin PySpark.
- **The catalog hands out the wrong S3 endpoint.** Many REST catalogs
  return storage config to the client. If yours tells Spark to use
  `http://minio:9000` (the in-Compose name), Spark on your laptop can't
  resolve it. Set the client-side endpoint explicitly, or run Spark
  inside the Compose network.
- **Path-style access off.** MinIO needs `bucket` in the path, not as a
  subdomain.
- **First run downloads jars** (`spark.jars.packages`) into `~/.ivy2*`.
  No network, no Spark. Later runs use the cache.

</details>

### 4. Prove the cross-engine read (30 min)

```python
from sideline_spark.session import get_spark

spark = get_spark("m7.5-check")
spark.sql("show namespaces in lake").show()
spark.sql("select count(*) from lake.marts.fact_play").show()
spark.sql("select * from lake.marts.fact_play.snapshots").show(truncate=False)
```

Compare the count with DuckDB's. Then compare the **snapshot ID** Spark
sees with the one DuckDB/PyIceberg reports as current. Same snapshot,
same data.

✅ **Checkpoint:** identical row counts and the same current snapshot
from both engines.

### 5. Write one table from Spark, read it from DuckDB (20 min)

The other direction matters too. Create a tiny table in a scratch
namespace from Spark, then read it from DuckDB or PyIceberg. Drop it
afterwards.

## Gotchas

- **Java.** `JAVA_HOME` must point at Java 17 or 21. A different Java on
  `PATH` in your IDE vs terminal makes "works in one, fails in the other".
- **Integration tests need the stack.** Mark them (e.g.
  `@pytest.mark.integration`) and decide whether CI runs them. CI has
  no MinIO unless you add services.
- **Don't commit `metastore_db/` or `spark-warehouse/`.** Spark creates
  them in the working directory if a catalog falls back to defaults. Add
  them to `.gitignore`; their appearance is also a sign your catalog
  config didn't apply.
